# Engine Lab experience

> Scope note: this document describes the historical Caterpillar prototype. The purchased generic V12 has a separate [native audit](../references/00_Active_V12/V12_NATIVE_AUDIT.md) and [migration plan](../references/00_Active_V12/APP_MIGRATION_AUDIT.md); these old specifications do not apply to it.

The application now presents one continuous dark engineering studio with three activities: Inspect, Operate and Learn. A compact inspector carries component context, the fixed-speed performance reference and the live guide. Hugeicons, neutral surfaces and a single warm primary accent create a consistent control language.

## Implemented experience

A first-visit welcome explains the public references, purchased exterior and authored internal model. Its replayable eight-step Driver.js presentation prepares and settles each real scene view before continuing. It demonstrates the assembly, explosion, section, moving cycle, chamber injection/ignition close-ups, published performance and a prepared AI question. The user chooses whether to send that final question. The same tour is available from the header, and leaving it pauses motion.

The canvas extends behind a black translucent header and inspector, with camera fitting that reserves their usable space. Cut controls are compact, slider thumb/track centers match, and fill lighting preserves visibility on dark materials. Fuel study provides paused injection (355°) and early power (420°) close-ups with a full-cylinder reset; these angles and chamber color cues remain teaching assumptions.

The purchased exterior retains 587 individually addressable source groups. Geometry picking and the library resolve the same stable IDs. Double-click selects, isolates and frames the visible component; section picking ignores cut-away surfaces. Exploded exploration includes individually addressable teaching internals, with a visibility switch. Focus, isolate, hide, remove, explosion, fit and restore use a shared scene-state contract. Native STEP recovery adds qualified vendor product labels to 569 groups; it does not invent a production bill of materials.

Operate offers a movable section plane through the combined engine, a dedicated single-cylinder study and a twelve-cylinder mechanism. Section controls expose axis, normalized position, retained-side reversal and guide visibility. Pistons and rods follow a constrained slider crank. The same 720-degree clock drives valves, injection cues and cylinder flow gates. The Cylinder study transport displays its visible cylinder's local phase; whole-engine section and full-mechanism playback use cylinder 01 as their reference. Slow-motion playback leaves the nominal 1800 rpm performance basis unchanged.

Five labeled systems can be enabled independently: charge air, exhaust, fuel injection, jacket water and lubrication. Their paths explain topology and direction. Tracer speed and color are visual encodings, not CFD velocity, pressure or temperature measurements.

Three lessons coordinate component selection, section view, cycle events and optional spoken narration. Speech starts after the scene settles; automatic progression waits for speech completion. Manual exploration suspends automatic cues. Stop cancels the guide, motion and audio; restore returns a saved view and sampled phase.

The live engineering guide runs the Codex harness against a browser-scoped scene MCP service. It observes current state, manipulates registered components and waits for execution acknowledgement. UUID-scoped runs reject late commands after Stop. The authored lesson/audio coordinator remains a UI capability; the current MCP tool set controls scene actions and reads lesson/audio status, but does not yet start arbitrary lessons or audio itself.

Private hosted guide access uses an invitation password and secure visit cookie; the provider key remains on the server. Local owner development can use the authorized environment key directly. The prepared hosting profile is one persistent Node container; public deployment and Linux runtime acceptance remain separate work.

## Engineering boundaries

The reference report remains EM1898-00, 1500 ekW standby at 1800 rpm. Performance distinguishes reported anchors, interpolated points and derived quantities. The moving mechanism is a deterministic teaching model; it is not a calibrated combustion, governor, thermal or acoustic simulation. The original STEP names include 3512B and have not been reconciled to a specific 3512C serial/arrangement.

## Next fidelity work

1. Match serial number, engine arrangement, ECM/software and performance revision to the geometry and documents. Recover or license verified production internals, valve/injection timing, cylinder numbering and firing sequence.
2. Review vendor component labels and material finishes with an engine specialist; replace heuristic system categories with a verified hierarchy where evidence permits.
3. Add a clearly parameterized load-step teaching model, then calibrate its inertia, actuator and governor response against measured traces. Fixed-speed reference points alone cannot validate transient behavior.
4. Expand the agent's acknowledged application commands to registered lesson and narration cues, with the same Stop and restore guarantees.
5. Validate the purchased-asset license and isolate the native agent runtime on the intended public hosting platform before enabling shared sponsored access.

The existing renderer stays in place while measured presentation-device results support it. WebGPU migration is a performance decision; it does not replace geometry, mechanisms, evidence or interaction design.
