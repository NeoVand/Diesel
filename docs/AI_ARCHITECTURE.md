# Engineering guide and live controller

> Scope note: this document describes the historical Caterpillar prototype. The purchased generic V12 has a separate [native audit](../references/00_Active_V12/V12_NATIVE_AUDIT.md) and [migration plan](../references/00_Active_V12/APP_MIGRATION_AUDIT.md); these old specifications do not apply to it.

Diesel runs the open-source Codex harness through `@openai/codex-sdk` in the SvelteKit Node server. The default guide model is `gpt-6-sol`, set with `DIESEL_AGENT_MODEL`; hosted visitors use this pinned server model. Optional advanced BYOK settings can choose an account-accessible guide model. Narration uses `gpt-audio-1.5`, configurable with `DIESEL_AUDIO_MODEL`. These are live integrations, with authored lessons and the presentation tour available without credentials. See the [Codex SDK documentation](https://learn.chatgpt.com/docs/codex-sdk).

## An observed tool loop

1. The browser registers its full lab state and component catalog at `/api/scene/session`, receives a random session bearer token, and opens the authenticated `/api/scene/events` SSE stream. It waits for the ready event before submitting a live question.
2. `/api/agent` receives the session, a browser-generated request UUID, bounded history, and either an optional visitor key or password-authorized server-key access. It creates a separate native-run token and an isolated temporary Codex state/workspace. The resolved key is scoped to this inference request; neither scene token is an OpenAI key.
3. Native Codex connects to the application's Streamable HTTP MCP endpoint, `/api/scene/mcp`, using the run token. A private `DIESEL_MCP_ORIGIN` can pin this callback to loopback HTTP or a trusted HTTPS worker; it never comes from visitor input. Its tools read current state, search exact components, compute reference operating points, retrieve curated citations, execute one action, and save/restore checkpoints.
4. A mutation passes the shared `LabAction` validator and current-revision check. The broker sends a command to the browser and waits. The browser applies the reducer, lets the renderer settle, captures actual phase/camera, and posts an acknowledgement. Only an `applied` result matching the requested state establishes success; stale, unavailable, cancelled, or timed-out operations report failure.
5. Codex receives that result and can query or act again. Instructions require a fresh `get_state` after the final operation. Its final JSON contains the explanation, validated source IDs, and `actions: []`: the browser has already executed the acknowledged operations. It does not replay an action list after the answer.

Commands control the demonstration: exact source/teaching components, selection, focus, removal, isolation, explosion amount, internal visibility, full-engine section plane, display, view, playback, pause/run, global cycle seek, flow overlays, bounded reference load, and saved snapshots. Checkpoints include internal visibility and all plane settings. Lesson and narration state are observable; starting a lesson or speaking a cue through MCP is not implemented. Manual lessons and narration use the page's coordinator.

`section` means a movable plane through the whole purchased engine and enabled authored internals; `cylinder` is the focused single-cylinder educational cutaway; `mechanism` is the full V12 teaching mechanism; `assembly` is the combined exterior inspection view. The plane uses a scene-axis normal (`x`, `y` or `z`), normalized offset 0–1, and a flipped retained side. Its `visible` flag shows the plane guide only: section display still clips when that guide is hidden. Source geometry may be open/non-watertight, so accurate complete cut caps are not guaranteed. The `internals` flag controls authored internal visibility in combined assembly/section views. Standalone cylinder/mechanism always show their teaching rig; individual hide/isolation controls still apply. Internal alignment, dimensions and explosion placement are illustrative, not verified matching OEM geometry or disassembly order.

In cylinder display, state includes the visible cylinder's sampled local phase, stroke and offset. In a whole-engine display, any focused/selected teaching cylinder is reported separately without implying the whole section contains only that cylinder. MCP seek is global: local phase is `wrap(global − offset)` and a desired local event requires `wrap(local + offset)`. The offsets are instructional, not authenticated Cat firing order. Recovered `cadProduct` strings are vendor STEP labels; stable `Frame_*` identities remain intact and their engineering function can still be inferred.

## Stop, state and session boundaries

Every run command, progress event, and cancellation echoes the browser request UUID. The browser ignores events from another request, orders accepted commands, and checks its generation around asynchronous work. Stop aborts inference, pending browser execution, lesson progression and audio; it also calls the broker cancellation endpoint. The next question waits for that cancellation before starting. Server cancellation revokes the run token, resolves pending operations as failures, and rejects late acknowledgements. Disconnecting the last SSE listener also cancels an active run.

Discrete revisions track accepted state changes. Animation samples update actual phase/camera without incrementing revision; older equal-revision samples cannot overwrite newer ones. Scene sessions, invite sessions, request allowances and concurrency counters live in one Node process. Sessions expire after 20 minutes without activity, while SSE heartbeats refresh active connections. Limits are 24 sessions, one active run per session, 24 operations per run, four concurrent guide requests and four narration requests. Live guide requests have a 90-second deadline; legacy non-session requests and narration have 45 seconds; each browser acknowledgement has 12 seconds.

## Credentials and isolation

The demo host stores `OPENAI_API_KEY` in private runtime environment/host secrets. Password access needs `DIESEL_DEMO_PASSWORD` (12 or more characters), `DIESEL_SESSION_SECRET` (32 or more characters), and an HTTPS application origin. `/api/access/unlock` validates the password with a timing-safe comparison and creates a random visit with a signed, host-only, HttpOnly, Secure, SameSite=Strict cookie. Cookie claims contain only version, random visit ID and issue/expiry times. The process-local ledger must also recognize the visit; a signature alone cannot revive a revoked or expired visit. Visits last two hours. Logout deletes the ledger entry and aborts active paid work, so replaying its cookie fails. Changing the signing/password/key configuration invalidates current visits when the next access request is handled. Restart invalidates all cookies.

`/api/access/status` and page data return only `AIAccessStatus`: mode, authentication/availability, expiry and remaining guide/audio request counts. They never return the key, password, signature or visit ID. Unlock/logout and every keyless paid request require a present, exact Origin; cross-site requests are rejected. Invited requests use the server-selected models, limit history to six entries of 2,000 characters each, and keep existing question/narration limits of 2,000 characters. Optional advanced BYOK stays in browser memory and sends its key only to the application's API over HTTPS. It does not consume the sponsored allowance; global capacity controls still apply. Credentials are never saved in browser storage or included in scene tokens. Application code does not log request bodies, passwords, raw upstream errors or audio; responses are `no-store`.

Each sponsored visit permits 30 guide and 30 narration attempts, with one paid request active at a time and limits of four guide/six narration attempts per minute. Address buckets permit 60 of each in a rolling 24-hour window; the process permits 200 of each per 24 hours. Password attempts are limited to five per address and 100 globally per 15 minutes. Buckets/session maps have fixed capacity, and cancelled/failed inference still consumes an attempt. Re-unlocking a valid visit preserves its quota. These are bounded request allowances, not an exact monetary spending cap: token costs vary, process restart resets counters, and cancelling cannot undo already billed inference. The shared-password gate is for a small invited demo, not an account/individual invitation system. Durable identity/usage storage is required before multiple workers or broader public access.

For the local owner, development mode plus a saved key and direct loopback URL/client addresses auto-enable keyless AI. `DIESEL_USE_LOCAL_SERVER_KEY=false` disables this convenience. Forwarded/proxy headers and cross-site requests are rejected; request Origin must match. Development status is determined by the built application, never a client-supplied localhost claim. Production has no local bypass, even if the TCP peer is a loopback proxy.

The Codex child has a small environment allowlist, ephemeral API authentication, an empty workspace, shell/apps/hooks/multi-agent/memory features disabled, disabled web search and command-network access, and a read-only sandbox. Temporary directories are removed in `finally`. This is not an operating-system security boundary: the installed native runtime still exposes some built-in helpers, including image/file-related helpers, alongside the MCP tools. An attempted `tools.view_image=false` override was not recognized by the installed version and is not relied upon. Production workers must run as unprivileged isolated processes/containers without unrelated secrets or private files mounted. A crash can leave temporary state until host cleanup.

## Evidence, audio and verification

Model context contains curated facts/source URLs, all twelve EM1898-00 anchors, and deterministic current/requested operating points. `get_operating_point` uses the same bounded interpolation as the UI. Engine performance remains a fixed-1800-rpm, 10–100% steady-state reference; mechanical timing, flows, materials and motion have explicit provenance. Source-ID validation prevents invented identifiers but does not prove each generated sentence; expert review remains necessary. See [simulation policy](../references/99_Archive/Caterpillar_3512_2026-09-29/07_Simulation_Data/GROUND_TRUTH_POLICY.md).

Narration uses Chat Completions, `alloy` voice and WAV output. Returned PCM chunks are validated; streaming RIFF/data length placeholders are normalized without changing samples. Truncated outputs are rejected. The browser aborts, pauses and revokes recordings on Stop or replacement. This is visibly labelled AI speech, not an engine recording, diagnostic acoustic model or sound simulation. See the [audio guide](https://developers.openai.com/api/docs/guides/audio-chat-completions).

Offline tests cover unauthenticated/wrong-password access, cookie tampering/expiry/revocation, logout cancellation, loopback spoofing, request allowances, server-key/model selection, boundaries, redaction, state/action validation, request UUIDs, cancellation, sampled-phase ordering, cylinder offsets, interpolation, WAV handling and cleanup. The native round-trip test launches the actual installed Codex binary against local mock inference and the real broker/MCP handler, then observes acknowledgement feedback before the final answer; it incurs no API charges. Owner-authorized live acceptance is recorded separately in [VERIFICATION.md](VERIFICATION.md). Those samples are not a complete factual, security or hosting evaluation.
